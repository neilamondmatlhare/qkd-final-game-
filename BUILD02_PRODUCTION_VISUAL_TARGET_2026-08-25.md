## Handling rule

This image sets the desired production outcome and quality bar. It is not proof that the present project already contains every pictured object, room, interaction, asset count or technology label. Do not fake those claims in-game or declare completion from a concept image alone.

It complements the canonical HQ spec, Master Build Contract, campaign memory and current user instruction. Exact room geometry, IDs and locked system constraints remain authoritative where more specific.

## Target experience

Phantom Q should read as one cohesive, living cybersecurity and quantum-engineering organisation from the exterior through the Secure Core:

- a strong evening/dusk arrival exterior with clear Phantom Q identity and a credible high-security facility;
- a warm, controlled Reception and Identity experience with visitor/credential verification, staff presence and a visible threshold into the organisation;
- Central Operations as the operational heart and WS04 anchor, visibly active rather than an empty generic room;
- eleven readable, distinct departments that each communicate an operational purpose through architecture, equipment, staff, lighting and interactable hero systems;
- restrained cinematic dark-neutral materials, blue/cyan operational light, department-specific accents and controlled contrast;
- professional 3D people/equipment and a raised-oblique cutaway view that remains readable as a game world;
- meaningful environmental motion: screens, access readers, doors, staff activity and campaign status should make the HQ feel operational.

Avoid the current failure mode of bright blown-out floor/emissive areas. The reference uses selective screen, signage and practical lighting against darker surfaces; legibility and mood must coexist.

## Learning/gameplay target

The image's macro loop is:

`Observe -> Investigate -> Respond -> Learn`

Use this as the campaign-facing shorthand. It complements, rather than replaces, the established object interaction loop:

`Brief -> Predict -> Configure -> Run -> Inspect -> Decide -> Explain`

Every department should support the macro loop through real room systems and campaign consequences. Examples: Foundations supports evidence reconstruction; Crypto supports protection/key workflows; SOC supports detection/correlation; Red Team supports scoped authorised response; Quantum provides later verified QKD capability.

## Scalable production intent

The visual target calls for a reusable foundation where future lesson modules, incidents, departments, HQ integrations, gameplay delivery and player progression can be added without rebuilding the entire facility. Treat this as an architecture and content-pipeline direction, not a licence to add empty placeholder rooms or unvalidated feature-count claims.

The image's phrases such as “100+ interactive systems”, “40+ custom assets” and “24/7 living HQ simulation” are aspirational delivery targets. They become reportable only when implemented and observed.

## Technology compatibility decision

The source image labels its illustrative stack “Unity 6 + HDRP”. The current active project is deliberately locked to Unity 6000.5.9f1 with URP 17.5.0. The user requested this image be captured as the build target; they did **not** request a render-pipeline migration.

Therefore:

- preserve the URP lock and pursue this image's visual outcome with URP;
- do not install/switch to HDRP or replace the renderer without an explicit user decision, impact review and renewed validation;
- preserve the local same-Wi-Fi/Raspberry Pi/Flask/SQLite authoritative-service baseline for QKD/hardware integration;
- use the image as direction for lighting, dressing, interaction density, exterior/reception quality and room identity, not as permission to claim unimplemented physical QKD integration.
