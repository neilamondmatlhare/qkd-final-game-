## Where the project is heading

Phantom Q Engineers is a persistent, industry-oriented cybersecurity and quantum-engineering learning/game platform. The player should move through a believable organisation, operate meaningful systems, make security decisions, inspect evidence, and progressively earn responsibility.

The four connected delivery blocks are:

- Game / Unity HQ: main playable world, missions, roles, progression, QKD, multiplayer.
- Website: project introduction, media, support shell and route into the demo/game.
- Video: trailer and demonstration using real gameplay/hardware evidence.
- Physical QKD: Alice/Bob/Eve hardware, calibration, telemetry, QBER and intrusion evidence connected back into the game.

These blocks connect, but none replaces the others.

## Non-negotiable experience locks

- One persistent HQ, not disconnected rooms or a level-select menu.
- Central Operations is the heart of the building; Workstation 04 remains a persistent anchor.
- Whole HQ first: Build 02 must finish as a complete playable production foundation before Build 03.
- Do not redirect Build 02 into an isolated QKD room or attractive one-room prototype.
- Object-led learning comes before long text: `Brief -> Predict -> Configure -> Run -> Inspect -> Decide -> Explain`.
- Security and QKD truth comes from authoritative simulation or physical hardware first; Unity animation only presents verified state.
- Sifted bits are not a final key. QKD establishes key material; encrypted file transfer is a later authenticated classical-channel demonstration.
- Alice, Bob, Eve and observer/control must remain role-safe during live QKD play. Hidden information must be filtered server-side, not merely hidden in a client UI.
- Eve is an authorised adversarial/security-test role, not automatically the culprit.
- Access authority is not a single numeric level. Use identity, role, capability, zone permission, mission grant and action/target authority.
- Current classroom deployment baseline is same-Wi-Fi clients with a local Raspberry Pi / Flask / SQLite authoritative service. Do not shift to hosted infrastructure unless explicitly decided later.
- Cyber-offence mechanics must remain fictional, scoped and authorised.
