# Phantom Q — Investor Evidence Execution Plan

The investor must be able to distinguish **designed**, **implemented**, **playable**, and **hardware-linked** work.

## Evidence pack

For every major capability produce a four-column proof frame:

| Design target | Unity implementation | Interaction / hardware evidence | Status |
|---|---|---|---|
| approved visual/diagram | deterministic capture from actual Build 02 scene | Play Mode or physical telemetry screenshot/video | Implemented / In progress / Planned |

Concept art can be visually ambitious, but it must be labelled **design target** until the game reproduces it. The value is in showing the conversion pipeline from idea to operational world.

## Investor sequence

3. Evidence-led Foundations.
4. Crypto + Communications security progression.
5. SOC → Red Team security depth and authority.
6. Engineering as real build/test capability.

9. Physical hardware telemetry entering the same authoritative state model.
10. Roadmap overlay showing later missions reuse the existing world instead of rebuilding it.

## Lesson-platform proof

The strongest scalability demonstration is not another menu. Show one room with two different lesson modules loaded into the same physical environment while the room shell, navigation, camera and equipment remain unchanged. The module changes objective, evidence, dialogue and allowed interactions.

That demonstrates the platform principle:

`one HQ + reusable systems + plug-in lesson definitions = many future learning experiences`
